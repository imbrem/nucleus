For implementers of the Rust kernel in
[#553](https://github.com/imbrem/nucleus/issues/553). Read
[the Covalence context](README.md) first for the trust architecture and the
claim-labelling convention used below; everything cited here was read at
[`0122507`](https://github.com/imbrem/covalence/commit/01225078f58260d3527f05bd3aa62ffa521e0eb6).

Two halves: the invariants that held up, and the places where things went
wrong. The second half is the more valuable one.

## Invariants that held up

### Locally nameless with anonymous binders

_[implemented]_ De Bruijn indices for bound variables, named free variables and
constants carrying their declared type. The important consequence is stated as
an invariant in `term/term.rs`:

> Binders (`Abs`) are anonymous — bound variables are pure de Bruijn indices
> with no display label — so structural equality on `TermKind` is exactly
> α-equivalence; rules can use `==` freely.

Storing a display name on the binder would break that, and every rule that
compares terms would need an α-equivalence walk instead of `==`. Keep binders
anonymous and put the pretty-printing hint somewhere that is not the term.

The Lean `Nucleus.HolLN` development already makes the stronger choice —
intrinsically scoped, with the bound-variable depth in the type index. Covalence
is the untyped-index version of the same representation, so the correspondence
is close enough to be useful and different enough to be worth checking rather
than assuming.

### Free variables carry their type, so typing is context-free

_[implemented]_ `Var` is `(name, type)` and both fields are part of its
identity: `Var("x", nat)` and `Var("x", bool)` are different variables, and
substitution only matches on both. The kernel design note calls out why this
matters:

> The enabling fact: **typing is context-free** (free variables carry their
> type), so `term : ty` holds in any context.

That is what makes a cached type sound to reuse anywhere, which is what makes
the whole performance story available. It is a representation decision with a
correctness consequence, so it is worth making deliberately rather than by
default.

### One sequent floor, and every path goes through it

_[implemented]_ `check_sequent` is nine lines: the conclusion type-checks and is
`bool`, and so does every hypothesis. Every rule bottoms out in a `seq` helper
that calls it, and the seam's landing constructor `Thm::from_pure` re-runs the
same helper — its doc comment says "so no landing path bypasses `seq()`".

The discipline is not the check. It is that there is exactly **one** check, that
new entrances to the theorem type are expected to call it, and that when one
genuinely could not, the exception was written down in the source with an audit
tag (see the hazards below).

### Rules derive their conclusions

_[implemented]_ No rule takes a conclusion as input. Each `decide` reads its
premises through a public accessor, checks side conditions, and builds the
conclusion itself. Soundness therefore reduces to which rule identifiers a tier
admits.

This is what makes the manifest meaningful. A rule that accepted a
caller-supplied conclusion would turn every caller into part of the TCB.

### Opaque theorems, opaque contexts

_[implemented]_ `Thm` is a newtype whose only constructors are the rule methods.
`Ctx` is an opaque newtype over a shared term set, exposing set operations and
nothing that could smuggle in an unchecked hypothesis. Hypothesis iteration
order is documented as stable-but-not-meaningful, and equality is set equality —
which prevents a whole class of "these two theorems have the same hypotheses,
but in a different order" bugs from ever mattering.

### Freshness by allocation, not by a global signature

_[implemented]_ `Thm::define` allocates a fresh `Arc` per call, and identity is
`Arc::ptr_eq`; the display name is transparent to `Eq`, `Hash`, and `Ord`. Two
`define` calls with the same name and the same body produce distinct constants,
so users cannot derive `⊢ body₁ ≡ body₂` by `trans` and `sym`.

> This is how we get freshness without a stateful kernel signature: the
> allocator gives us a unique pointer per call.

`new_type_definition` does the same with dedicated `FreshId` tokens for τ, `abs`,
and `rep`. Critically, all of it is allocated **inside** the rule's `decide`,
never taken as an input, "so an adversary cannot force a collision".

The idea — freshness is generated by the rule, never supplied to it — transfers
directly. The mechanism does not: see the process-local identity hazard below.

### Checked adapters around untrusted construction

_[implemented]_ `term/cons.rs` is the cleanest example of a pattern Nucleus will
need repeatedly. Two traits:

- `TrustedCons` is **sealed**. Its contract — the returned term is structurally
  equal to the requested kind — is relied on by the kernel, so downstream code
  cannot implement it.
- `TermCons` is the public, untrusted mirror. Anyone may implement it: a custom
  interning policy, a content-addressed store, a WASM bridge. It carries no
  guarantee.

The bridge is a `Checked` adapter that lets the untrusted constructor produce a
term, re-checks the result structurally, and falls back to a fresh allocation if
it returned anything else. In the module's own words, an arbitrary `TermCons`
becomes a `TrustedCons` "with the guarantee restored by verification, not by
trust".

Note also _why_ this is safe to make pluggable at all: sharing is purely a
performance concern, because term equality is structural with a pointer-equality
fast path. Interning "can never change a proof". Establish that property first;
the pluggability follows from it.

### Caching that is honest about what it caches

_[implemented]_ Each node carries a summary computed once at construction:
`Open { bvi }` (the largest free de Bruijn index), `Wf { ty }` (closed and
well-typed), or `IllTyped`. A type is cached **only when the node is closed**,
which given type-carrying free variables makes it context-free and safe to reuse.

Two accelerators ride along in bytes that would otherwise be padding: a 32-bucket
Bloom filter over free-variable names, with the only guaranteed property being no
false negatives, so substitution and occurrence checks skip whole subtrees; and a
16-bit Merkle-style structural fingerprint, so comparison can reject distinct
terms in O(1) without walking a shared prefix.

_[inference]_ The pattern generalises past this representation: cache only what
is context-free, and make each accelerator's guarantee one-sided so that a
failure degrades to slow rather than to wrong. The Bloom filter cannot cause a
wrong answer because "maybe present" falls through to the exact check.

## Hazards, with evidence

Every item here is something Covalence hit. These are the checks worth having
from day one, before the code that would need them exists.

### 1. A native operation disagreeing with its own definition

**The confirmed soundness bug.** _[implemented]_, fixed. When a constant is
reachable by _both_ a computation certificate and definitional unfolding, the
kernel commits to two things at once: `spec lit… = reduce(spec lit…)` and
`spec = body`. From `notes/vibes/kernel/kernel-design.md`:

> Consistent only if the body denotes the same function the certificate computes,
> on every input — a divergence makes the theory inconsistent.

It diverged. The third audit pass (2026-06-14) found that `nat.mod n 0` reduced
to `0` while its body evaluated to `n`, which **derived `⊢ 0 = 5`**. The fix
changed the certificate to return `n` and added
`audit_reduce_matches_body`, which bites exactly when a body reduces to a
literal — forcing the Euclidean conventions `x/0 = 0` and `x mod 0 = x` to be
chosen once and honoured by both paths.

A fourth pass found a second instance of the same shape: for a definition-style
spec that is also certificate-reducible, the kernel commits to both the defining
predicate and the certificate values, so "every function satisfying `p` must
agree with the certificate on reducible inputs". Also guarded, by
`audit_reduced_def_specs_satisfy_their_predicate`.

**For Nucleus.** The general hazard is any pair of paths to the same fact. Do
not add a fast path for a construct that also has a slow path without a
differential test between them, and prefer having only one path until the
performance need is measured. If the JSON kernel ever gains a native evaluator
alongside definitional unfolding, this is the test to write first.

### 2. A fast path stamping a false cached type

_[implemented]_, fixed. Found by property tests, not by review. The `open_with`
fast path _trusted_ the body's well-typedness instead of verifying it, and was
reachable from the safe public API with an ill-typed body. Two failures, one of
them soundness-class:

> `open(λ:nat. (#1 #0), 5u8)` returned `λ:nat. (5u8 #0)` with cached type
> `Ok(nat → u8)` even though the term is ill-typed — breaking the cached-type
> invariant every kernel rule trusts.

The fix makes the fast path verify inline and abort to the slow path on any
failure.

**For Nucleus.** A cache that can be wrong is an axiom. The safe shape is the
one used in the fix: the fast path must be able to _decline_, and declining must
fall back to the checked path rather than to a guess.

### 3. Panics reachable from the public API with attacker-supplied terms

_[implemented]_, fixed. `Thm::beta_conv` type-checked only the argument of the
redex, so an ill-typed abstraction body — `(λx:nat. #5) 0` — sailed past the
checks and panicked inside a helper's `expect`. The test file is blunt about the
exposure: "a panic reachable from the safe pub kernel API with attacker-supplied
terms (untrusted proof scripts drive `beta_conv`)". A fail-stop rather than a
soundness hole, since the conclusion is re-validated, but a denial of service on
exactly the untrusted input path.

Relatedly, `shift_by` panics on de Bruijn index underflow and overflow **by
design** — silently wrapping an index would let an unsound term propagate. What
makes this defensible is that `panic_envelopes.rs` carries an audit list of every
trusted caller and the precondition each establishes, with a "keep in sync"
instruction.

**For Nucleus.** Deliberate fail-stops are fine; undocumented ones are not.
If a trusted helper panics on a precondition violation, the list of callers that
establish the precondition belongs next to the property test that pins it.

### 4. Process-local identity does not survive serialization

_[implemented]_, by design, and the deepest structural mismatch with where
Nucleus is going. Covalence's freshness rests on `Arc` pointer identity, and
pointers are not deterministic across processes. The consequences are documented
in three places:

- **Serialization refuses.** `sexp.rs`: "the kernel's `TermKind::FreshConst` /
  `TypeKind::FreshTyCon` leaves are **process-local** `Arc` identities; there is
  no cross-process representation that preserves their unforgeability, so
  serialising a term containing one is an error."
- **Round-tripping a defined constant mints a new one.** Parsing `(def NAME
BODY)` calls `Thm::define` again, deliberately, because "`Def` identity is a
  per-process `Arc` pointer, not a serialisable concept".
- **Content hashing ignores it.** `hash.rs`: fresh leaves hash by structural
  payload only, so "two distinct fresh constants of the same type therefore
  collide". Sound for the `Hash`-vs-`Eq` contract, and a trap for anyone who
  assumed a content hash identifies a constant.

**For Nucleus.** This is the pattern to _preserve_ and the mechanism to
**reject**. Nucleus is JSON-first and content-addressed; identity has to be data.
Whatever replaces the `Arc` — a hash of the defining equation, an explicit index
into a checked environment — must be assigned by the kernel rule and must be
unforgeable without being a pointer. Design it before writing `define`, not
after.

### 5. Content hash tags that are not yet stable, and say so

_[implemented]_ `hash.rs` carries a section header reading "Tag values are NOT
stable yet", explaining that the encoding is in flux, that there is no persisted
backwards compatibility to preserve, and — usefully — that nobody should add
"reserved, do not reuse" bookkeeping until the format is committed to.

**For Nucleus.** Exactly the posture
[#569](https://github.com/imbrem/nucleus/issues/569) asks for: documenting the
experimental HOL JSON format does not freeze it. Say so in the format document
itself, the way this file does, and say when that changes.

### 6. Theorems serialize one way

_[implemented]_ `sexp.rs` serialises theorems and refuses to parse them back.
The bridges reconstruct instead. `mm_replay.rs` — Metamath propositional
calculus into HOL — is the model:

> The Metamath proof is **untrusted** — the verifier's say-so is _not_ trusted
> for the HOL theorem; the kernel re-checks each rule.

It walks the proof and re-derives every step through ordinary kernel rules,
landing in _derivability over encoded syntax_ rather than denotation, so the
bridge is proof-irrelevant: it certifies that a derivation exists by
reconstructing one. The WASM facade states the same principle in one line:
"Host-side selection of a rule is not proof authority."

**For Nucleus.** Construct, don't trust. An imported theorem is a hint about
which rules to apply, never a fact. This is the invariant that makes it safe for
the untrusted half of the system to be arbitrarily large — which, in Covalence,
it is.

## Checklist for the Nucleus kernel

Concrete, in roughly the order they become possible.

- [ ] One sequent/well-formedness floor, called by every rule and every
      construction path into the theorem type. Zero exceptions, or a written
      audit obligation per exception.
- [ ] Every rule derives its conclusion; none accepts one.
- [ ] Theorem and context types are opaque, with no constructor that bypasses
      the floor.
- [ ] An enumerable list of admitted rules, generated from the same source as
      the rules themselves so the two cannot drift, and checked in.
- [ ] A generated TCB report — files, non-test lines, mint sites, `unsafe`
      count — with a ratchet that fails CI when it grows.
- [ ] A naive reference implementation of substitution, opening, and closing,
      and a property test asserting the optimised path agrees with it on
      randomised terms over the real vocabulary.
- [ ] Substitution lemmas as properties: open/close round trips, shift inverses
      and composition, the substitution commutation lemma, type preservation,
      α-stability of renaming.
- [ ] Property tests over **ill-typed and ill-scoped** inputs, not just valid
      ones. Both fixed panics above were on invalid input reachable from the
      public API.
- [ ] Every cache honest: nothing cached that is not context-free, and every
      fast path able to decline into the checked path.
- [ ] Freshness allocated inside the rule, never supplied to it, and expressible
      as data rather than as a pointer.
- [ ] If two paths can ever establish the same fact, a differential test between
      them — before the second path lands.
- [ ] Serialization is one-way for theorems; importers replay through the
      kernel.
- [ ] Panic preconditions documented with their trusted-caller audit list, next
      to the property test that pins them.
